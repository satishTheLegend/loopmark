# Shared expansion contracts

I01 freezes the first executable contract in `src/domain/contracts.ts`, `schema.ts`, `policy.ts`, `errors.ts`, `canonical-json.ts` and `revisions.ts`. No provider-specific types cross these ports. The existing seven portable types remain available through `src/types.ts`; `portable.ts` and `portable-schema.ts` hold their unchanged definitions. Portable v1 inline data URLs are distinct from normalized wire media references. Local IndexedDB migration is the next package, not an I01 side effect.

## Version and scope

Wire `protocolVersion: 2`, payload `1`, portable backup `1`, legacy IndexedDB `1` and the expansion repository schema version are independent. IDs retain the portable 1–80 ASCII letter/digit/underscore/hyphen grammar; local namespaces use `guest_<uuid>` or `account_<uuid>` (no colons). Collection keys always include namespace, collection ID and epoch. Local session generations are nonnegative safe integers, distinct from server account-deletion and device generations. Repository activation establishes the generation before mutation; all asynchronous writes must match it.

Server revisions/cursors/sequences are canonical decimal strings from 0 through PostgreSQL signed bigint maximum; sequences begin at 1. Existing facade library revisions remain UUID/timestamp/`empty` values. Never coerce either representation into the other.

## Command and revision semantics

Every command carries collection/epoch/device/generation/sequence/operation identity, version, immutable base and SHA-256. All commands are strictly validated, then canonicalized recursively with sorted object keys, preserved array order, UTF-8 and SHA-256 excluding only `sha256`. Unicode is preserved without normalization. Isolated UTF-16 surrogates, U+0000, undefined, nonfinite numbers, cycles, sparse arrays and nonplain objects are rejected. Fixed independent hash vectors live under `tests/fixtures/expansion/`. PostgreSQL stores only validated JSON-compatible commands. Authenticated server session identity supplies ownership; no owner or entitlement flag is accepted in the command.

| Kind | Base target | State change and receipt |
|---|---|---|
| `project.create` | Null; new unique project ID/code | Insert project at the transaction revision; `project.put` |
| `project.update`, `project.status` | That project's revision | Update the project and revision; `project.put` |
| `project.delete` | That project's revision | Tombstone project and checkpoints; each deleted entity appears in changes |
| `checkpoint.create` | Parent project's revision | Insert immutable checkpoint and advance parent revision/updatedAt; receipt contains both puts |
| `media.attach` | Checkpoint's revision | Validate reservation/owner/project, attach verified media, advance checkpoint and parent revisions; both puts |
| `collection.replace` | Explicit collection revision from preview; predecessor base forbidden | Atomically replace using validated reservation, new epoch; `collection.replaced`; old pending work is recovered |

Every successful mutation advances collection revision and transactional cursor under the collection lock. All affected entity revisions equal that transaction revision. The server validates parent links and makes no network call inside the transaction. A predecessor base resolves only a matching target's `put` in a receipt from the same epoch and collection; `predecessorRevision` defines that mapping. The server also verifies the receipt's stored collection/device ownership. It compares the resulting revision with the target's current revision, so intervening remote edits remain conflicts. A delete receipt cannot authorize recreating a deleted entity. Equal operation ID/hash returns its immutable original receipt; changed hash rejects.

`SyncTransport` returns successful validated values and throws `DomainError` for typed failures. `ConflictError extends DomainError` carries validated `{operationId,current,expected}` for comparison UI. Adapters never retry internally: the coordinator owns bounded retries. Abort only cancels transport; a server commit may already exist, so retry/lookup uses the same operation ID and hash. `BoundaryResult` covers platform cancellation/unavailability and includes `mayHaveCommitted` for mutation-aware cancellation.

## Repository and media

Repositories store acknowledged shadows separately from ordered pending commands. `commitLocal` validates generation, computes local view/sequence/command and commits atomically. Guest changes do not create network outbox work. Connected intents and their immutable wire commands are committed with the visible local result. `markAttempt` never rewrites an assigned command. Acknowledgement reconciles the matching hash/operation and removes only that pending intent; it must not advance the contiguous pull cursor. Pull-page changes, intent reconciliation and cursor commit together. A pull before acknowledgement must not duplicate the local effect; older acknowledged puts never overwrite higher revisions. Empty pulls are valid with unchanged cursor. Each nonempty page must contain consecutive transactional cursors starting at afterCursor + 1; a missing entry rejects the entire page. Compacted/expired cursors require rebase, never a silently accepted gap.

`importLocal` atomically installs an already validated candidate (with immutable durable media) and provenance, bypassing commercial create limits while retaining technical limits. Replacement requires the exact local revision and generation and is allowed only for a local collection; connected replacement uses the server reservation/epoch command. `retainLocal` takes a consistent revision-fenced copy of visible saved work into a new retained local collection, preserving source content. `removeLocal` removes only the named device copy, is revision/generation fenced, and never calls server deletion. Media references must be prepared/copied into the destination scope before the reader switch; orphan cleanup follows the reference rules.

`readAcknowledged` returns the durable server shadow with an empty pending list, allowing a conflict comparison to survive restart. `resolvePending` accepts only a conflict/rejected operation and its transitive `afterOperationId` dependents. Against the exact reviewed local revision and active generation, it atomically retains their affected visible projects and immutable history in a named recovered collection, retires only that closure, and optionally commits a fresh replacement intent/sequence/hash against the current acknowledged revision. Attempted payloads are never rewritten. A replacement operation ID must be new; response-loss retries cannot duplicate it. Missing recovery bytes block retirement without changing either collection. A remote deletion can be accepted with a local recovered copy, never silently resurrected. Decide later does not call this port. Both adapters implement the same pure closure rules and durable-state tests. This port was added during caller integration before any expansion release.

`hydrate` validates all pages from one protected snapshot before a single reader switch. Every manifest echoes `after`: null for the first page, then exactly the preceding page's `nextPage`. The final `nextPage` is null. Empty/non-string cursors, omitted/repeated/interchanged pages and inconsistent snapshot ID, collection, epoch, revision or cursor reject the entire hydration. This required field was added during the I02 independent review before any expansion release; both server and clients consume the corrected protocol2 contract. `recoverPending` preserves pending values in a named recovered collection before old-epoch hydration. `snapshot` pins all referenced bytes until `releaseSnapshot`; drafts remain separate and outside exports. `contract-suite.ts` is a reusable real-adapter test, not evidence of native storage correctness by itself. I02/I04 must execute it plus fault/concurrency suites against actual stores.

Media preparation/open/release always receives immutable collection scope; preparation, verified ingestion and destructive release additionally check session generation, and release checks live references. `storeVerified` caches bytes under the exact server/imported media ID after verifying MIME/kind/size/hash; it rejects a conflicting ID rather than overwriting immutable bytes. A late callback after sign-out cannot promote a prepared file. Duplicate IDs in unrelated imported/guest/account collections cannot address each other's files. MIME handling preserves existing WebKit spaced/quoted codec parameters. `portableMediaBytes` returns the entire JSON string-value byte size, including outer quotes, escaped codec quotes and exact base64 padding. When replacing a metadata placeholder `""`, subtract that placeholder's two bytes before adding this value; total portable size is still the exact sum of serialized v1 project objects. Bytes, reservation limits and project access limits are separate invariants.

## Authority and failures

Three active free projects is a create/reopen policy. Read/history/export/edit/checkpoint/finish/delete remain available over capacity. Legacy access preserves only local collections and never grants connected access. `deriveUpgrade` consumes verified server ledger grants for one billing principal and environment; it is not a verifier and must never accept arbitrary SDK/client input. Failed/disputed/refunded/revoked grants do not confer access; any independently valid grant does. Billing adapters report submitted/pending/cancelled/none/failure, never a trusted paid result.

Safe errors include stable code, useful problem/cause/action, retry policy, correlation ID and bundled offline help. Unknown exceptions are redacted. Deletion receipt schemas expose status/times/help only; receipt tokens are sent by POST and never included in this returned data. Cloud responses and snapshot manifests must validate before any durable write. Authorization, CAS, reference integrity and quota checks belong to actual server transactions in I03/I07/I08; a TypeScript type is not enforcement.
