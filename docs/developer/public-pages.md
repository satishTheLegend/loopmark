# Public help and private app routes

`npm run build` renders `/privacy`, `/support` and `/delete-account` into `dist/<route>/index.html` before the service worker manifest is generated. These are complete static HTML pages, so they remain readable with JavaScript disabled. This deliberately replaces the proposed three React page components: the private app remains React, while public help does not need an app session or runtime. `src/pages/public-pages.ts` is their single content source and `public/public-pages.css` uses the existing self-hosted Lora/DM Sans design.

Vite development and preview explicitly map all three routes, trailing slashes and `/index.html` variants. A static production host must serve each exact public path from its directory's index file **before** its general SPA fallback. Do not rewrite `/privacy` to the private app's index. The files also remain directly available at `/privacy/index.html`, `/support/index.html` and `/delete-account/index.html` for hosts without clean-URL support. This is a hosting requirement, not a deployed-host verification.

Without a configured HTTPS `VITE_LOOPMARK_APP_ORIGIN`, every page remains noindex and robots blocks indexing. With that validated origin, only the three public content pages get canonical URLs and sitemap entries; app/account/auth/deletion-receipt routes remain private and noindex. Indexing controls do not replace account authorization. The service worker bypasses API, Auth, REST, Storage and Edge function paths. Only compiled static assets and explicit public help pages use its offline cache.

`LOOPMARK_PUBLIC_SUPPORT_EMAIL` optionally supplies a plain public support mailbox. It cannot contain a mailto URL, headers or markup. Missing contact is disclosed as unavailable rather than inventing an address. Before public service activation, supply the actual operator contact and reviewed account/payment retention disclosures. No live service contact, jurisdictional retention term, domain, service enrollment or provider account is established by these pages. Account availability copy reflects public cloud configuration, which does not itself activate backend enrollment.

The build validates all public Vite settings before generating a bundle. Unsupported public settings fail with a redacted configuration error, preventing accidental secret publication. Invalid runtime configuration still falls back to guest mode through the existing startup configuration boundary.

Verification is in `tests/expansion/privacy-routes.spec.ts`: no-JavaScript pages, metadata, reflow at 320/390/768/1440, keyboard navigation, axe, offline navigation and deliberately poisoned API-cache bypass. WebKit uses its supported Option+Tab traversal for links. Browser keyboard evidence is separate from physical VoiceOver/TalkBack qualification. The public-content generator has additional tests for scope, conditional cloud copy, canonical URLs and header/HTML injection in the support contact.
