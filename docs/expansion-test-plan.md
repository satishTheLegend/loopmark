## Key Interactions and codepath diagram

```text
Capture ─> local prepare ─> record + outbox ─> visible local save
                 │ failure preserves draft       │ account generation changes
                 └─ native crash recovery        └─ retain/recover, never cross account
Outbox ─> dependency → auth → command → receipt + feed
          │ retry same ID    │ CAS conflict      │ lost response → retry
          └─ stale epoch/device → recovered copy└─ pull + shadow + overlay
Media ─> reserve → stage → hash → attach → download → offline-ready
          └─ quota/expiry/delete/failure → pending + remedy
Backup ─> pinned manifest + all bytes → compact JSON → independent restore
          └─ incomplete/changed/expired → no false full-backup result
Purchase ─> login + intent → provider → durable inbox → per-grant reconcile
             └─ cancel/pending       └─ refund/restore/recovery → derived access
Delete ─> persisted receipt → generation barrier → live purge → backup expiry
             └─ response loss → receipt query    └─ no late-work resurrection
Release ─> local tests → native build → real sandbox + devices → external activation
```

## Failure injection and oracle

Use independent fresh readers and hash/count comparisons after process restarts. A test is insufficient if it only asserts a mock was called. Inject transaction abort, network loss before and after server commit, reordered responses, account generation change, lease expiry, provider timeout, disk exhaustion and native process death. Retry the same command with its original hash. Verify both data preservation and actionable UI state. Real provider/store cases record sandbox transaction IDs privately and redact screenshots; no actual charge is authorized by this plan.

Existing regression commands remain `npm run build`, `npm test`, `npm run test:e2e`. Run `npx playwright test tests/scale.spec.ts --project=chromium --workers=1` on its isolated reference fixture. New test scripts/fixtures are implemented by the execution packages; their commands do not work merely because this document names them. Backend tests use local Supabase/pgTAP plus HTTP concurrency integration; native tests use XCTest and Android instrumentation on real persistence adapters. Fake payment tests do not replace store sandbox tests. No LLM behavior is added, so prompt/model eval suites are not applicable.
