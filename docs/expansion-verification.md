The backup defect was fixed by using authoritative live object inventory: a historical logical attachment whose underlying object has already been garbage-collected is not a missing live object. A real upload/delete/GC/backup regression retains failure for genuinely missing ready objects. The load harness records raw failures separately from eventual outcomes and uses stable IDs with bounded retries consistent with the production client's 5xx handling.

The first 1,000 burst exposed an Auth classification defect: temporary identity-provider failures were returned as permanent `AUTH_REQUIRED`. Infrastructure failures now return retryable `SERVICE_UNAVAILABLE`, with a bounded identity-check deadline; verified revoked/deleted sessions still return `AUTH_REQUIRED`. An actual controlled outage/recovery and invalid-session regression passed. The later stress run records zero AUTH_REQUIRED responses and all 1,000 accounts recovering their original commands in 13.992 seconds. A 315,787-byte SQL argument exceeded Docker’s per-argument limit; sending the same query through stdin fixed the verification harness. The same-cohort read-only exact audit and explicit auxiliary continuation passed. The original failed burst remains a local capacity failure, not a hosted capacity claim.

The final 1,000-account burst also failed to complete its concurrent encrypted backup; the exception detail was not retained, so its exact cause remains unknown. Resuming the same recovery point after pressure completed with 145,322,609 verified bytes. Ten deliberately truncated reservations remain quota-accounted (655,360 bytes) with zero corresponding physical objects; expiry and bounded maintenance are separately tested, and this cohort is not claimed already swept. See [limitation details](evidence/expansion/load/backend-1000-limit-clarifications.json).

The first observer also found a navigation race: a late initial project-link resolution could overwrite a newer navigation choice. App now checks the current URL before publishing that result. The observer now journals each measured save, uses bounded action timeouts and writes a unique report for every run.
