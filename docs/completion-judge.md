## Data and lifecycle review

Inspected `data.ts`, media validation, BackupView, draft forms, App routing, Dialog, offline state, worker generation and changed CSS. The repository keeps each saved mutation and its operation receipt in one IndexedDB transaction. An operation token cannot be reused for different content or project; deletion and restore clear relevant receipts. Library replacement compares a whole-library revision within the destructive transaction, so a stale confirmation cannot discard another tab's later work without renewed review. Import validation precedes destructive writes, imported photos are decoded, and external/executable media remains rejected. JSON/media roundtrip checks use actual playable/decodeable fixtures.

Drafts are deliberately separate from exported saved records, and the backup screen explains that distinction. This means domain commit and draft cleanup cannot be one database transaction; receipt recovery is essential, not cosmetic complexity. The review specifically challenged cleanup failure, concurrent edits, explicit discard and navigation because happy-path persistence alone does not establish safe interruption handling.

No new remote request, telemetry, authentication boundary or HTML execution sink was introduced. Existing private-app indexing protections remain. Browser persistence permission reduces eviction risk and does not become a backup guarantee. Real microphone/camera quality, OS eviction, physical print/scan, speech assistive technology, hosted delivery and human study outcomes cannot be inferred from these local tests.
