# Local backend load evidence

The final 100-account run completed every workload phase. The first 1,000-account simultaneous burst exceeded this shared local runtime’s capacity. Its failed result is retained in `backend-1000-initial.json`; it is not a passing production capacity measurement. A separate bounded post-pressure recovery run will retain the original burst status and replay the same in-memory immutable commands.

Both runs used actual local Auth, PostgreSQL, Edge functions, private Storage, and a concurrent encrypted recovery point. The payment/network fixture is explicitly synthetic and does not qualify a payment-provider sandbox. The host had severe unrelated load and swap pressure; Docker had about 8.32 GB assigned. Raw response latency includes errors and is not successful-request latency.

The 100-account run (`6bb9c741-daf2-445d-88b4-ffdaeec5a05a`) completed 100 owner-denial checks, ten interrupted and recovered media uploads, twenty duplicate signed webhook deliveries resolving to one inbox row and grant, twenty-five controlled typed overload responses, fair aged-data compaction across retained accounts, and a complete 38,718,178-byte encrypted recovery point. There were two raw HTTP503 responses; identical retries converged. Its 21.728-second measured interval excludes Auth setup.

The first 1,000-account run (`5194df8d-dbeb-42eb-891b-c4154f2e2570`) failed 882 pipelines during the simultaneous burst. A post-stress read-only audit selected exactly those 1,000 synthetic setup accounts: 422 receipts, 422 matching feed entries, 249 projects and 173 checkpoints; no duplicate operations/sequences, effects without receipts, collection-owner mismatch, staged objects or inflight uploads. There were 103 pending observation rows. These checks establish committed-effect consistency, not convergence of the failed pipelines.

The workload exposed an application bug: `getUser` infrastructure failures were classified as `AUTH_REQUIRED`. The corrected function retains retryable `SERVICE_UNAVAILABLE` for timeout/transport/provider failures, while authoritative invalid or revoked sessions remain `AUTH_REQUIRED`. Actual exact-profile Auth pause/resume, unchanged-command retry, invalid-token and deletion-session tests verify the distinction. The first full regression run caught the SDK’s special `AuthSessionMissingError` subtype; that failed run is preserved and the subtype corrected without weakening assertions.

The 1,000-account burst also produced untyped gateway failures. Retained exact-profile Edge logs in its interval contain 60 `WorkerAlreadyRetired`, 132 `InvalidWorkerCreation`, and 12 CPU soft-limit events. The original harness did not retain transport exception causes, so those causes remain unknown. The refined harness records a safe allowlist of transport codes and separates burst metrics from bounded recovery metrics.

Earlier attempts remain summarized in `backend-load-attempts.json`. They include the corrected backup inventory check (logical historical media versus current physical objects), missing transient handling in auxiliary fixture requests, a non-deterministic rate-bucket timing fixture, and a mistaken grant-column assertion. The final 100-account result follows those corrections. A controlled exhausted synthetic rate bucket proves the typed admission response; it is not presented as naturally observed saturation throughput.

Root-owned `capture-*.json` artifacts record local application capture during selected load intervals, including full reload/export verification. They are separate from server convergence and capacity results.
